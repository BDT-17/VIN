\begin{abstract}
\noindent
% --- One paragraph framing the task and the gap (motivation + limitation) ---
Data augmentation by object insertion - adding a target object to an
existing image while preserving the original background and its annotations -
is constrained by a fundamental tension: a single diffusion pass asked to both
synthesise the object and leave the scene untouched will, in practice, rewrite
background pixels and corrupt the very labels the augmented data is meant to
support. Prior families soften but do not close this gap: full-image img2img
rewrites the global scene, masked inpaint still lets generated background leak
inside the edit region, and training-free attention injection places objects well
yet offers no guarantee that pixels outside the object are returned unchanged. The
flows are also reported on incompatible, per-method metrics, so no apples-to-apples
comparison exists.

% --- One paragraph: what this work proposes ---
This report studies a background-as-source-of-truth architecture in which
the original image is the trusted scene and generated background pixels are
discarded. We compare two insertion flows built on Stable Diffusion~3.5
Medium - (i)~a context--object composite augmenter (\textsc{V5}) and (ii)~a
concept LoRA followed by segment-and-paste (\textsc{LoRA}) - under
a single shared, dependency-injected metric core, so the two become directly
comparable for the first time. The central design choice is to make background
preservation a structural property - both flows return the
source image with only segmented object pixels composited in - rather than a
behaviour the generator is merely asked to respect.

\section{Introduction}\label{sec:intro}

\subsection*{Global context and motivation}
Supervised object detectors and segmenters remain data-hungry, and the classes
that matter most are often the least represented: rare poses, crowded scenes,
unusual scales. Synthetic object insertion - placing a new, plausible
instance into a real image - is an attractive way to enlarge such data, because
it promises new positives without new photography or new manual labels. The
promise holds only if the inserted object is realistic enough to be a valid
positive and the rest of the image is left exactly as it was, so that every
annotation already attached to the scene stays correct.

We use CityPersons pedestrian insertion~\cite{citypersons} as the reference
experiment. Pedestrians are a deliberately hard, useful test case: they span a
wide range of scales, must be grounded on a plausible surface (feet on the
ground, not floating), are frequently occluded by scene structure, and admit a
strong off-the-shelf validator in a person detector~\cite{yolov8}. A method that
handles pedestrians well therefore exercises scale, grounding, occlusion, and
detector-based validation at once. The task is nonetheless framed as object
insertion in general, not pedestrians specifically; the detector, prompt set,
placement policy, and validation rules are the parts that specialise to a class.

The cost of getting it wrong is asymmetric. A convincing pedestrian pasted onto a
background whose pixels have shifted is worse than no augmentation at all: the new
instance may be a usable positive, but every pre-existing box, mask, or class
label on that frame is now attached to pixels that no longer match it. Background
corruption silently poisons the dataset, which motivates an architecture in which
background fidelity is not something the generator is asked to preserve but
something the pipeline guarantees by construction.

\subsection*{Literature review and research gaps}
% The sample splits prior work into generations and names a gap per method.
Insertion and editing methods can be read as successive attempts to enlarge the
canvas the model may touch while shrinking the damage it does to everything else;
each generation removes one failure mode and exposes the next.
\begin{itemize}[leftmargin=1.4em,itemsep=2pt]
  \item Full-image img2img - adds objects but rewrites the global scene.
  \item Patch / tight-mask / bbox inpaint - progressively more canvas,
        but generated background inside the edit region still leaks in.
  \item Training-free attention-injection insertion (\eg Add-it~\cite{addit2025})
        - strong placement and no fine-tuning, but it blends in latent space and
        decodes the whole frame, so pixels outside the object are not guaranteed
        identical to the source, and its constants are derived for a different
        (FLUX) backbone.
\end{itemize}
These limitations share a root cause: background preservation is treated as a
behaviour to be encouraged (by a mask, a prompt, or an attention bias)
rather than a property to be enforced. The gap addressed here is therefore
twofold: an architecture that makes preservation structural across heterogeneous
flows, and a single metric core under which those flows can finally be compared on
the same numbers.

\subsection*{Problem statement}
% The sample states the task formally with notation + a numbered requirement
% list + the domain-specific challenges. Reproduce that shape.
Let $I_{\mathrm{src}} \in \mathbb{R}^{H\times W\times 3}$ denote a source image
and let $c$ be a target-object specification (class, prompt, optional placement
prior). The insertion task is to learn or apply a map
$\mathcal{F}\!:\!(I_{\mathrm{src}}, c) \to I_{\mathrm{out}}$, with
$I_{\mathrm{out}}\in\mathbb{R}^{H\times W\times 3}$, satisfying four
requirements: \textbf{(i)~object validity} - a detectable, correctly-classed
object of plausible appearance is added; \textbf{(ii)~scale and grounding} -
the object's size and contact point are physically plausible for the scene;
\textbf{(iii)~background preservation} - pixels outside the object region are
unchanged relative to $I_{\mathrm{src}}$ (\bgmae$\,\to 0$, \bgssim$\,\to 1$); and
\textbf{(iv)~label integrity} - the augmented sample remains valid training
data for the downstream task.

\noindent Three challenges constrain any solution.
\textbf{(1)~Diffusion denoising can alter any visible pixel.} A single pass that
re-noises and re-decodes the frame has no mechanism that leaves a chosen region
bit-for-bit untouched, so background preservation must be enforced architecturally
(segment the object, composite onto the original), not requested through a prompt
or a mask alone. \textbf{(2)~Plausible appearance does not imply correct scale.}
Generated objects routinely look realistic yet sit at the wrong physical size or
float off the ground, because the generator has no explicit geometric prior; scale
and grounding must be corrected after generation from depth or placement cues.
\textbf{(3)~Detector-guided validation is practical but not human-quality.} Using
a detector as both extractor and validator makes the pipeline self-checking and
reproducible, but detector confidence is a proxy: it can accept an artefact a
human would reject, so quantitative gains must be read alongside qualitative
inspection.

\section{Objectives}\label{sec:objectives}

\subsection*{General objective}
The overall aim is a background-preserving object-insertion pipeline for dataset
augmentation in which background fidelity is guaranteed by construction, and in
which several insertion strategies can be evaluated on a single shared metric core
so their quality and cost are directly comparable. CityPersons pedestrian
insertion is the reference task, but the design is intended to generalise to other
object classes by swapping the detector, prompt set, placement policy, and
validation thresholds.

\subsection*{Research questions}
% Sample organises around 3 RQs; keep that count tight.
\begin{enumerate}[label=RQ\arabic*.,leftmargin=2.4em,itemsep=2pt]
  \item Can object insertion preserve the background by construction
        (segment-and-composite) rather than by prompting, across diverse scenes?
  \item Does a concept LoRA, trained to generate people and then segment-and-paste
        them, integrate objects better than the prompt-driven V5 augmenter, once

  \item What is the quality--cost trade-off across the two flows - what does
        each added component (training, scale correction, validation) buy
        in preservation or inclusion, and at what runtime and memory cost?

\section{Materials and Methods}\label{sec:methods}

\subsection{Model selection}\label{sec:model-selection}
Both flows share a single generation backbone: Stable Diffusion~3.5 Medium in
FP16/BF16~\cite{sd35}. The backbone is used only for inference-time candidate
generation; it never sees the final background, because
a detector/segmenter extracts the object and the pipeline composites it onto the
untouched source. Selection was therefore driven less by peak photorealism than by
fitness as one stage of a retry-heavy, segmentation-and-composite pipeline:
candidate-object realism, prompt adherence, controllable img2img behaviour,
stability under repeated retries, practicality on a Kaggle T4 16\,GB, and
compatibility with detector-guided validation. FP16/BF16 is preferred over 4-bit
(NF4) because outputs are more stable and prompt/strength/guidance comparisons are
cleaner; NF4 is kept only as a low-VRAM fallback. \Cref{tab:models} lists the
backbones considered and why each is not the default.

\subsection{Diffusion backbone: MM-DiT and rectified flow}\label{sec:backbone}
Both flows share a single generation backbone - Stable Diffusion~3.5
Medium - so their architectural differences lie entirely in how each
conditions that backbone, not in the backbone itself. We summarise the
backbone here so the per-flow descriptions can refer to it.

\paragraph{From U-Net to a latent transformer.}
Like prior latent diffusion models~\cite{sdxl}, SD3.5 operates not on pixels but
in the latent space of a pretrained autoencoder: an image
$I\in\mathbb{R}^{H\times W\times 3}$ is encoded to a latent
$x\in\mathbb{R}^{h\times w\times c}$ (here $h=w=64$, $c=16$ for a $512$\,px
image), denoised there, and decoded back. The denoiser is a Diffusion
Transformer (DiT)~\cite{dit} rather than a U-Net: the latent is split into
non-overlapping patches, each linearly embedded into a token, and the resulting
token sequence is processed by a stack of transformer blocks. DiT injects the
conditioning signal (timestep, class) through adaptive layer
normalisation (adaLN-Zero) - per-block scale/shift parameters regressed from
the conditioning embedding - which~\cite{dit} found to outperform both
cross-attention and in-context token conditioning.

\paragraph{MM-DiT: two streams, one attention.}
SD3 generalises DiT to text-to-image with the multimodal MM-DiT
block~\cite{sd3}. Image patches (with positional encodings, from $2\times2$
latent patches) and text tokens are embedded to a common width and concatenated
into one sequence; two separate sets of weights process the two
modalities - effectively two parallel transformers - that are joined
only for the attention operation, so each modality keeps its own
representation while still attending to the other~\cite{sd3}. Text conditioning
comes from three frozen encoders (CLIP-L, CLIP-G, T5-XXL): the pooled CLIP
vector plus the timestep drive the adaLN modulation, while the T5/CLIP token
sequence enters as the text stream. In our runs T5-XXL is disabled by default to
fit the T4 16\,GB budget, leaving the two CLIP encoders; this trades some
fine-grained prompt fidelity for memory, which is acceptable here because the
prompts are short object descriptions rather than long compositional scenes.

\paragraph{Rectified flow.}
SD3.5 is trained as a rectified-flow model~\cite{sd3}: rather than the
DDPM variance schedule, the forward process is the straight-line interpolation
\begin{equation}\label{eq:rf}
  X_t = (1-\sigma_t)\,x_0 + \sigma_t\,\epsilon,
  \qquad \epsilon\sim\mathcal{N}(0,I),\ \sigma_t\in[0,1],
\end{equation}
and the network predicts the velocity $v_\theta$ along this path. Sampling
integrates the corresponding ODE with a FlowMatch-Euler scheduler.
\Cref{fig:genflow} shows the generation flow common to both flows.

\subsection{Dataset}\label{sec:dataset}
The composite-augmentation flow draws pedestrian source frames from three
datasets, each with a fixed role (\cref{tab:dataset}). CityPersons~\cite{citypersons}
- $2{,}975$ train / $500$ val images with roughly $35{,}000$ annotated persons, a
bounding-box subset of Cityscapes - supplies LoRA candidates from its train
split, while its validation split is frozen for evaluation and never trains the
LoRA. MOT17-02~\cite{mot17} contributes $600$ frames ($1920\times1080$, sampled at
$2$\,fps over $2$\,s windows to avoid consecutive-frame redundancy), and a
human-detection set contributes its positive (person) images; both are LoRA
candidates only.

The concept LoRA is trained on images from Paint-by-Inpaint / PIPE~\cite{pipe}:
$888{,}000$ train and $752$ test items at $512\times512$, spanning $824$
\texttt{Instruction\_Class} categories drawn from COCO and OpenImages. The
concept flow uses the person-class images as plain generation targets (PIPE's
before/after pairing is not required to train a generator); we keep only person
classes, and the frozen evaluation set is the PIPE test split ($752$ items),
person-only.

Splits are group-aware - by scene (CityPersons), sequence time-window (MOT17),
or perceptual cluster (human detection) - so near-duplicate frames cannot
straddle train and eval. The LoRA train/val split is $85/15$ (seed $42$) after a
quality filter (minimum bounding-box height $96$\,px, visible ratio $0.45$, quality
score $0.70$), and the frozen eval pool is itself partitioned $70/30$ into a
dev/tuning set and a touch-once final holdout (seed $42$). The split is therefore
scene-disjoint by construction. \TODO{fill the post-filter per-source counts from
the ETL run.}

\subsection{Flow A - Context--object composite (\textsc{V5})}\label{sec:v5}
\textsc{V5} treats the MM-DiT backbone (\cref{sec:backbone}) as a black-box
img2img candidate generator and places all background-preservation
logic outside it. The motivating observation is architectural rather than
empirical: because rectified-flow denoising (\cref{eq:rf}) can in principle move
any latent token, no prompt or guidance setting guarantees that pixels
outside the intended object stay fixed - so \textsc{V5} never asks the model to
preserve them. Instead it generates a candidate, segments only the new
object, discards the generated background, and composites the object onto the
untouched source. The original image is the source of truth; generated
background pixels are never trusted. The pipeline is a fixed sequence of
explicit stages:
\begin{equation}\label{eq:v5}
  \begin{aligned}
  &\text{placement}\to\text{context generation}\to\text{segmentation}\to\\
  &\text{scale correction}\to\text{compositing}\to\text{validation}\to\text{retry}.
  \end{aligned}
\end{equation}

\paragraph{Stages.}
\textbf{(1)~Placement} proposes a valid insertion region from object-specific
priors (road/sidewalk masks, existing person/vehicle boxes, depth ordering,
overlap checks) - placement is a policy, not a prompt, since a realistic
object in an invalid location still corrupts the dataset.
\textbf{(2)~Context generation} runs SD3.5 img2img over a local context crop, so
the model has enough surrounding scene to produce a coherent, correctly-lit
candidate (the lesson from the V1--V4 ablations: too little canvas yields ghosts;
too much rewrites the scene).
\textbf{(3)~Segmentation} extracts the new object with YOLOv8m-seg.
\textbf{(4)~Scale correction} estimates expected pixel height from
depth/ground-position, resizes the crop and mask together with the contact point
(feet) anchored, and rejects objects outside a plausible size envelope -
geometry, not text, governs scale.
\textbf{(5)~Compositing} cleans the mask, trims the generated-background fringe,
applies occlusion rules against foreground persons/vehicles, harmonises
colour/brightness/texture/edge (optional contact shadow), and alpha-pastes only
the object pixels.
\textbf{(6)~Validation + retry} re-runs the detector and geometry/background
checks; weak samples are rejected and regenerated under a bounded budget rather
than saved.

\paragraph{Quality score and safety gate.}
\textsc{V5} keeps a fused quality score as a flow-specific extension (not part of
the shared core of \cref{sec:metrics}):
\begin{equation}\label{eq:v5score}
  Q = 0.45\,s_{\text{obj}} + 0.25\,s_{\text{scale}}
    + 0.20\,s_{\text{bg}} + 0.10\,s_{\text{edge}},
\end{equation}
used for analysis and conservative autotune guidance, not as a claim of absolute
image quality. By policy augmentation is restricted to the \texttt{train} split
so it cannot contaminate the evaluation benchmark - \texttt{target\_splits}
is set to \texttt{train} only. \Cref{fig:v5arch} draws the staged flow of
\cref{eq:v5}, with the trusted-background path highlighted.

\subsection{Flow B - Concept LoRA + segment-and-paste
(\textsc{LoRA})}\label{sec:lora}
\textsc{LoRA} separates the two responsibilities that the harder mask-free
\emph{edit} variant conflated: \emph{what to generate} (learned by a LoRA) and
\emph{which pixels to keep} (enforced by construction at paste time). The
current flow takes the simpler of the two paths - it learns to \emph{generate}
people, not to \emph{edit} a given scene - and then recovers the background by the
same segment-and-composite principle as \textsc{V5}.
\textbf{Implementation note:} an earlier mask-free \emph{edit} LoRA conditioned the
denoiser on a source latent (an InstructPix2Pix-style~\cite{ip2p} image path with
a trainable input projection and two-scale CFG) was prototyped but retired; the
flow in the repository today is the plain text$\to$image concept LoRA described
here, with segment-and-paste as the compositing step.

\paragraph{Training: a plain text$\to$image concept LoRA.}
A single LoRA is trained, DreamBooth-style, so the frozen SD3.5 backbone learns to
\emph{generate} images in the distribution of the PIPE ``add a person'' subset.
There is no mask, no source image, and no image-conditioning projection: training
is the standard SD3 rectified-flow objective on the target latent alone,
\begin{equation}\label{eq:lora-cond}
  z_t = (1-\sigma_t)\,z_{\text{img}} + \sigma_t\,\epsilon,\qquad
  \mathcal{L} = w(\sigma_t)\,\big\lVert \hat v_\theta(z_t,t,c_{\text{text}})
  - (\epsilon - z_{\text{img}}) \big\rVert^2 ,
\end{equation}
where $z_{\text{img}}=\text{VAE}(\text{image})$ and $c_{\text{text}}$ is the
precomputed text embedding. Only the attention LoRA adapters are trained; the
MM-DiT weights and the three text encoders stay frozen, and text embeddings are
precomputed to disk so the encoders can be dropped during the T4-budget run
(bf16 compute, fp32 trainable). Inference therefore needs a single artifact -
\texttt{adapter/pytorch\_lora\_weights.safetensors} - and no input projection.

\paragraph{Why PIPE images.}
The concept LoRA is trained on the person-class subset of PIPE~\cite{pipe}: real
photographs that contain people, used as plain generation targets (the
before/after pairing that PIPE was built for is not needed here, since the LoRA
generates rather than edits). The loader filters strictly on the
\texttt{Instruction\_Class} field (whole-word person classes; the free-text
caption is never matched, so a non-person image cannot leak in). Of PIPE's
$888{,}000$ images only the person-class subset is retained (the exact count is
logged by the loader at train time).

\paragraph{Generate $\to$ segment $\to$ paste.}
Background preservation is an inference-time composite, not a training objective:
\begin{enumerate}[leftmargin=1.6em,itemsep=2pt]
  \item \textbf{Generate.} Base SD3.5 + the trained LoRA run the standard
        rectified-flow denoise loop from the prompt alone, producing a full image
        that \emph{contains} a person. The model never sees the original scene, so
        the generated background is its own - not the target's.
  \item \textbf{Segment.} YOLOv8-seg (COCO class~0) returns a per-person
        $\{\text{mask},\text{bbox},\text{conf}\}$ from the generated frame; low-confidence
        or tiny detections are dropped.
  \item \textbf{Paste.} The segmented person is composited onto the
        \emph{original} background. The mask is eroded a pixel or two to drop the
        YOLO background halo, the alpha is feathered for a soft seam, and a
        Reinhard colour transfer shifts the person's per-channel mean/std toward
        the pixels it covers (optional OpenCV Poisson \texttt{seamlessClone} for
        the largest person). Pixels outside the person are byte-exact by
        construction - a composite, not a learned or hard-restore approximation.
\end{enumerate}
\textbf{Known trade-off:} the pasted person was lit by the \emph{generated} scene,
so a paste can read as a sticker; mitigations are to raise the colour-match
strength or enable Poisson blending. The flow does not control \emph{where} the
person lands (the prompt-only generator gives no placement prior), which is the
price of the simpler concept-LoRA path relative to a scene-conditioned editor
such as FLUX.1 Kontext~\cite{kontext} - the latter keeps the edit in one model
pass but gives no byte-exact background guarantee, the property this flow
prioritises.

\subsection{Shared metric core}\label{sec:metrics}
% This is the project's distinctive methodological contribution; give it space.
Both flows are evaluated through one dependency-injected metric module
(\texttt{shared\_metrics.py}; \texttt{numpy}${}+{}$Pillow${}+{}$an injected
detector callable). The shared set is component-only (no fused score):
\begin{itemize}[leftmargin=1.4em,itemsep=2pt]
  \item \textbf{Detection} - \textsc{person\_detected}, \textsc{person\_confidence}.
  \item \textbf{Inclusion} - did a new object appear vs.\ the source?
        (detector count delta).
  \item \textbf{Scale} - \textsc{scale\_ratio}, \textsc{scale\_error} vs.\ an
        expected height; \texttt{None} (not a false~1.0) when no prior exists.
  \item \textbf{Background preservation} - \bgmae / \bgssim over pixels
        outside the object region, where the region is taken from
        (priority order) an explicit mask (LoRA), an explicit bbox (V5), or the
        detector boxes.
\end{itemize}
Each flow retains its own metrics as extensions (V5: affordance/placement;
LoRA: \textsc{edge\_seam}, \textsc{outside\_mask\_*}).
Cross-flow comparison pairs rows by $(\text{case\_id},\text{seed})$ via
\texttt{paired\_shared} and reports per-metric means, deltas, and a direction-aware
improvement flag driven by \texttt{SHARED\_METRIC\_DIRECTIONS}
(\cref{tab:shared-metrics}). The shared core is covered by 10 tests (numpy/PIL plus
a fake detector, no torch) in \texttt{tests/test\_shared\_metrics.py}.

\subsection{Discussion}\label{sec:discussion}
Read against the research questions, the comparison shows that background
preservation can be made structural (RQ1): the segment-and-composite flows
return the background unchanged because those pixels are copied, not denoised, so
their residual \bgmae reflects only object-region accounting, not scene drift.
Whether the learned concept LoRA integrates objects better than the
generation-driven V5 augmenter once both are reduced to the same paste step
(RQ2), and what each component costs (RQ3), are answered by \cref{tab:main} and
\cref{sec:efficiency} once measured.

Several limitations are stated plainly. Detector-guided validation is a proxy, not
a human-quality judgement, so a high person confidence does not certify a clean
insertion; smoke tests are noisy and should not be over-trusted; the paste flows
can exhibit sticker-lighting; and if any data split is not fully scene-disjoint,
the corresponding numbers should be read as optimistic. \TODO{add or remove items

\section{Conclusion and Perspective}\label{sec:conclusion}
This report studied a background-as-source-of-truth architecture for
object-insertion augmentation, in which the original image is trusted and generated
background is discarded, together with a single dependency-injected metric core
that makes two otherwise incomparable insertion flows - a composite augmenter
(V5) and a concept LoRA with segment-and-paste - report the same numbers on the
same cases. The
contribution is therefore as much methodological (comparability) as architectural
(structural preservation). \TODO{state the headline result and the quantified
trade-off in one or two sentences once measured.}

Future work follows the codebase's own generalisation path: rename the
pedestrian-specific abstractions to \texttt{target\_object}, add open-vocabulary
detectors so new classes need no bespoke detector, strengthen matting to reduce the
sticker-lighting artefact, add dataset adapters beyond CityPersons, and, most
importantly, evaluate downstream - measure whether a detector trained on the
augmented data improves, not only whether the inserted images score well on visual
metrics.
